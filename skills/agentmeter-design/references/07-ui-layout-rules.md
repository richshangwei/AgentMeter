# 07 桌面與平板版面規則

> 目錄：產品流程 → 卡片拓撲 → Fit-to-viewport 演算法 → 視覺語言 → 驗證矩陣 → 常見陷阱

**核心原則（來自使用者否決過的兩次設計）：**
1. 桌面監控畫面**必須塞進視窗，不出現捲動區**。「用捲動可以到達」不等於「可讀」——使用者否決了巢狀捲動；當內容放不下，**減少每頁卡片數（分頁）**，而不是加捲軸。
2. 監控成員與順序的管理放在**設定**，不佔用主畫面（曾經的「新增磚」吃掉了監控空間，已移除；主畫面零個 add tile）。
3. 版面拓撲由**可見卡片數**決定，不由 viewport 啟發式決定。

## 1. 卡片拓撲（精確矩陣）

| 可見卡片數 | columns × rows |
|---|---|
| 0–1 | 1 × 1 |
| 2 | 2 × 1 |
| 3 | 1 × 3（垂直） |
| 4 | 2 × 2 |

- 每頁最多 4 張（`pageSize = 4`）；12 個監控以 4 張一組分頁。
- 只有目錄項目（catalog-only，如尚未有 collector 的 Cursor / Kiro）**不能變成資料卡**，也不會預設選取。
- 選擇值需過濾：只保留 `available` 內的字串 id、去重；`moveDesktopMonitor` 在邊界處不動。
- 隱藏的 grid 列會改變隱式放置（`display:none` 的 `.dashboard-head` 曾讓 `.cards` 落入第二個 auto 列而塌成 106px）→ **App shell 子元素要給明確 `grid-row`**，並驗證「從別的尺寸 resize 後」而不只是全新載入。

## 2. Fit-to-viewport 演算法

```
卡片形狀   寬高比 ≥ 2.6 → wide，否則 normal
最小卡片   normal 290×210；wide 520×112
密度       wide：高<170 → tight / regular
           normal：寬<360 或 高<280 → tight；寬≥620 且 高≥440 → roomy；其餘 regular
最小磚     90×56 px
每頁容量   依序嘗試 count、min(count,2)、1：
             計算卡片矩形；小於最小卡片 → 換下一個
             估算 quota 區域；若 size>1 且最密卡片的磚低於 90×56 → 換下一個
             通過 → 回傳（size===count ? 4 : size）；全失敗 → 1
```

**磚排版 `quotaTileLayout(width, height, count)`**：在區域內枚舉欄數，挑「min(磚寬/250, 磚高/112) × (1 − 0.03 × 空格數)」分數最高者（磚寬上限 560、高上限 260）。依磚高選變體：

| 條件 | 變體 |
|---|---|
| 高 ≥ 92 且內容高 ≥ 56 且環旁留白 ≥ 120 | `ring`（環＋右側文字；依空間決定標籤 1/2 行、重置 1/2 行、是否顯示已用） |
| 高 ≥ 150 且堆疊環 ≥ 56 | `stack` |
| 高 ≥ 56 | `bar` |
| 其他 | `line` |

所有字級／尺寸由**磚矩形推導**，使「內容高度（行盒＋間距＋padding）」在選定變體前就已知會放得下。完整標籤、重置、用量放進 tooltip。

## 3. 圓環與數字（兩個被抓到的視覺 bug）

- **偽元素的繪製矩形也要被驗證**，不只驗證外框。曾在 2491×1312 上主環被上緣切平，因為 `.quota { overflow:hidden }` 加上 flex 把 `.quota` 壓到小於兩個窗口的最小高度合計。
- **數字大小必須跟著圓環內徑**（內徑 ≈ 外徑 69%）。用最寬的有效值（`100%`）測，而不是只測現有 fixture；可見文字寬度須 ≤ 內徑的 90%。
- 同格的兄弟元素（週期標籤 vs 數值）不得相交：用獨立 grid 欄位，不用依賴寬度的百分比 margin。

## 4. 視覺語言

- 深色底（深海軍藍）＋半透明玻璃卡、圓角、青色邊光；字型 Segoe UI Variable／系統堆疊；數字加粗。
- 品牌色：Claude 橘、Antigravity 紫、Copilot 藍、全域狀態青／薄荷。
- 圖像資產（品牌符號、Provider 圖示、空狀態插圖）使用**透明底的實際點陣圖**，不用 inline SVG／CSS 插畫／文字替代；不得有棋盤格殘影。
- 文案為繁體中文，**保留真實的配額/狀態語意並區分未知與零**。
- 可及性：按鈕可鍵盤聚焦；狀態文字保留給輔助科技；目標尺寸夠大；顏色之外要有文字標籤。

## 5. 驗證矩陣（缺一就不能說「版面完成」）

- **尺寸**：實機尺寸與 DPI 縮放後的 CSS 等價成對測試（如 2491×1312 與 1993×1050），並含 2048×1190、1873×1135、1498×908、952×1235、762×988、1080×640、640×520、1440×900、1280×720、375×844、844×390。
- **張數**：每個尺寸都跑 1/2/3/4 張卡。
- **資料**：**真實基數**（8 個 Codex 窗口、4 個 Antigravity 窗口）、小數（24.7%）、`100%`、長重置文字、unknown / error / usage-only 狀態、過期標記。
- **斷言**：無任何 `.app-shell`/`.cards`/卡片/quota 區域可捲動或溢位；內容矩形包含於最近的裁切祖先；同層矩形不相交；主要資料與動作都在每張可見卡與對話框內；回歸時要有「未變輪詢保留 DOM 與閱讀位置」的測試。
- **操作**：resize 序列（從不同尺寸變到目標尺寸）、設定頁（1080×640、1440×900）、對話框、鍵盤。
- 工具：Playwright（以 `NODE_PATH` 指向）跑 Chromium；這**不等於** Windows/Edge 的 Segoe UI 度量——要在報告中註明未在目標平台驗證的部分。

## 6. 沒有 UI 的 Console 閃爍

背景收集若偶爾閃出 CMD／Windows Terminal，要**用觀察者驗證**：觀察者本身需要正向對照（刻意開一個可見 console，確認觀察者看得到），否則「零個視窗」的結果沒有意義。不要只靠程序旗標或靜態測試宣稱已修好；重現嘗試要橫跨第三方 CLI 的更新 TTL（Antigravity 最多每 15 分鐘檢查一次更新）。
