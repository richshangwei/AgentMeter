# Authenticated browser end-to-end handoff — 2026-09-09

Single-agent verification using the real mock-provider host and Codex in-app browser.

## Verified in an actual browser

- Opened the loopback landing page from a running `agentmeter-tablet-host` process.
- Entered the host's short-lived mock-only pair code and established an authenticated browser session.
- After one transient first-connect error, page reload successfully exchanged the HttpOnly Device Pair for a new Tablet Session and fetched a complete four-Provider Dashboard Snapshot.
- The rendered snapshot visibly contained Codex, Claude, Copilot and Antigravity with canonical setup, paused, Availability, Collection State, Freshness, Data Quality, Collector Maturity and Failure Code fields. All values were clearly marked as mock data.
- Requested Codex refresh from the browser. The request showed accepted status and a later SSE snapshot advanced revision from 1 to 2.
- Reloaded again; automatic pair recovery succeeded and fetched revision 2 without re-entering a code.
- Stopped the host. Within the reconnect interval the browser changed from connected to a warning that the connection was interrupted and displayed values might be stale.

The browser tab was closed, the mock host was stopped, and the desktop preview started for a separate control inspection was explicitly exited. The short-lived mock session is no longer usable. No durable pair store, ADB mapping, real Provider Account or user credential was involved.

## Limits and finding

The first immediate connect after pairing displayed a transient disconnected state; reload recovery then succeeded twice. This should be diagnosed before treating first-connect UX as stable. The test used a desktop-sized in-app browser, not a physical tablet or tablet sleep cycle. Host restart with DPAPI persistence, expired-session recovery, missed-event recovery, accessibility, resource/latency measurements and the monitor-only boundary on a real tablet remain open.

The desktop Tauri window was also opened and the current Claude path/save/forget/load/watch controls were visibly present. A third-party overlay and incomplete WebView focus reporting prevented reliable automated text entry, so source-path save/restart/forget is not claimed as interactively verified in this batch.

Formal checklist remains **47/79 checked, 32 open** because no compound physical-tablet acceptance criterion is fully satisfied. This batch materially strengthens browser evidence without redefining the target. Changes remain uncommitted.
