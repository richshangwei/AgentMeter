# Ticket 07 USB loopback P0 evidence

The fixture-driven experiment is implemented by `agentmeter-usb-p0`. It models an explicit ADB serial, separate host/device ports, loopback-only binding, no-rebind conflict detection on the selected device, authenticated reachability, browser-launch separation, reconnect events, and owned teardown. Reverse namespaces belonging to another device are no longer misclassified as a selected-device conflict.

The healthy fixture proves the expected supported shape. The browser-only fixture remains offline until an authenticated health response succeeds. Dedicated fixtures prove an unauthorized selected serial fails with an actionable diagnostic, an explicit physical serial wins when emulator/TCP/offline devices are also present, and an unknown selected-device mapping fails closed without disturbing the unrelated-device entry.

Reproduction:

```text
cargo test --offline --locked --test usb_loopback -- --nocapture
```

Result on 2026-09-06: 6 passed, 0 failed.

Real ADB/device validation is unavailable in this environment: ADB is not discoverable and no authorized Android device serial was provided. `tablet-http-p0-2026-09-07.md` now proves the loopback-only authenticated listener over real TCP, but not the ADB/device side. Selected-device USB transport is therefore **blocked for v1 publication** and Ticket 07 remains `needs-info`.

An operator must record the selected redacted serial, physical USB transport, host/device port pair, `adb devices -l`, per-device `adb -s <serial> reverse --list`, the exact `reverse --no-rebind` result, authenticated `/health` result, and targeted teardown. Repeat for unauthorized, offline, emulator/TCP mixture, occupied selected-device mapping, unplug/replug, ADB restart, host restart, tablet sleep, and stale mapping. Confirm unrelated devices and mappings are byte-for-byte unchanged. Browser launch must be recorded separately and must not make `browser_session_online` true.
