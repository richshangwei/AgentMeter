# Claude statusLine P0 evidence — 2026-09-06

## Result

**Constrained; not supported for a v1 release yet.** The offline experiment proves a reversible wrapper seam, preserves prior statusLine output, refuses to overwrite a configuration changed after installation, normalizes quota-bearing events, preserves missing quota as unknown, and labels the log fallback `estimated` / `experimental`. It does not prove the contract against a real Claude installation or Provider Account.

`claude` was not discoverable on `PATH` in the test environment, so no Claude version, plan, authenticated event, or real before/after configuration is claimed.

## Reproduction

```powershell
cargo test --offline --locked --test claude_statusline -- --nocapture
```

The test uses an isolated temporary settings file. It checks install/enable/disable/remove, prior-command output passthrough, post-enable configuration conflict handling, structured quota normalization, missing quota, malformed/schema-changed events, and the separately degraded log fixture.

Every failure in the offline matrix has the same canonical envelope: Provider, unknown Provider Account, replay-marked Source, Data Quality, Collector Maturity, Availability, Collection State, Freshness, Failure Code, diagnostics, and a null Observation. The covered cases are:

| Case | Availability | Collection State | Failure Code |
|---|---|---|---|
| Missing event | `available` | `idle` | `missing_event` |
| Malformed payload | `available` | `error` | `malformed_payload` |
| Configuration conflict | `setup_required` | `error` | `configuration_conflict` |
| Prior statusLine command exits unsuccessfully | `available` | `error` | `command_failed` |
| Unsupported event/schema | `available` | `error` | `schema_changed` |

The prior-command failure is exercised through the actual wrapper subprocess boundary and its structured diagnostic is emitted on stderr so failed statusLine output cannot be mistaken for a valid display result.

## Required real-install gate

1. Record `claude --version`, plan/account scope, Windows or WSL Source, and test time.
2. Copy and sanitize the existing statusLine configuration; preview the wrapper change before enabling it.
3. Confirm the pre-existing command's visible output is unchanged while AgentMeter receives a representative event after the first provider response.
4. Capture one quota-bearing event and one valid event with no quota fields; remove identifiers and secrets.
5. Repeat the offline failure matrix against the real installation and confirm user edits made after enable are not overwritten.

Until that gate passes, the integration requires explicit opt-in setup and remains `experimental`; missing events or quota remain unknown.
